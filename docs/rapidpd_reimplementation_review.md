# RapidPD 算法流程与第一轮代码复现差异审查

> 本文是 Git 标签 `rapidpd-round1` 的审查记录。当前第二轮实现及参数以 `docs/algorithm.md` 为准。

审查依据：用户提供的 RapidPD 作者版论文，重点为第 5–8 页、式 (9)–(19) 和 Fig. 2；当前 MATLAB 源码；DesayCPD 参考工程。结论针对当前代码版本，不把论文没有公开的实现细节当成已知事实。

## 1. 论文能够确定的算法流程

对每一个 Tx-Rx CSI 流分别处理。

1. **CSI 提取**：获得时间-子载波 CSI 矩阵 `H(t, fi)`。论文平台工作在 5775 MHz、80 MHz，两个 Tx 天线、一个 Rx 天线，得到两个 Tx-Rx 流；每包 234 个可用子载波，采样率 20 packet/s。
2. **仅保留幅值**：舍弃相位，使用经过 AGC 补偿后的 `|H(t,fi)|`，见式 (9)。
3. **逐包幅值归一化**：
   - `s(t) = Σ_i |H(t,fi)|`，式 (10)；
   - `H_tilde(t,fi) = |H(t,fi)| / s(t)`，式 (11)。
   目的在于消除每包所有子载波共同变化的增益误差。
4. **建立一秒窗口**：20 个包组成一个窗口，窗口步长一秒，即论文实验使用不重叠的连续窗口。
5. **估计环境基准**：在当前窗口内按时间求平均：`H_bar(fi)=1/T Σ_t H_tilde(t,fi)`，式 (12)。
6. **基准相减**：每包减去窗口均值：`H_D(t,fi)=H_tilde(t,fi)-H_bar(fi)`，式 (13)。
7. **第一层子载波维自相关**：对每个时刻 `t` 的整条 `H_D(t,:)` 沿子载波维计算：
   - `rho_1(t,v)=gamma(t,v)/gamma(t,0)`，式 (14)；
   - 论文实际计算式为 `gamma_hat(t,kΔf)=1/K Σ_{i=1+k}^K H_D(t,f_{i-k})H_D(t,f_i)`，式 (16)。
   这里不是沿时间计算 ACF，而是对一包 CSI 的频率序列计算 ACF。
8. **三层自相关**：论文选择 `n=3`。正文和其引用的多层自相关文献说明：把上一层自相关输出当作新序列，再做自相关。论文式 (17) 的排版却只显示上一层除以其零延迟值，缺少“对上一层重新求自相关”的运算，按字面执行不会形成新层。因此递推的边界、双边/单边序列、每层长度、是否重新去均值不能从论文唯一确定。
9. **单包运动统计量**：取最终层在一个子载波间隔处的值：`psi_n(t)=rho_n(t,Δf)`，式 (18)。
10. **窗口内汇总**：论文称 `phi` 为 average motion statistics，但式 (19) 写作 `phi=Σ_t psi_n(t)`，缺少 `1/T`。Fig. 6 的 0–1 数值范围更接近平均值，但论文没有给源码消除这一矛盾。
11. **多流汇总**：论文明确写 `Phi=Σ phi`，即所有 Tx-Rx 流求和，得到 overall motion statistics。
12. **判决和平滑**：`Phi>=eta` 判为存在；论文实验选择 `eta=0.43`。连续 `m=3` 个窗口的判决取多数作为最终输出。

## 2. 与当前代码的逐项对照

| 环节 | 当前实现 | 审查结论 |
|---|---|---|
| 幅值 | `abs(CSI)` | 与论文方向一致 |
| AGC 补偿 | 没有显式执行；直接使用 PicoScenes 返回的 AX210 CSI | **未证明等价**。论文式 (9) 的输入是 AGC-compensated amplitude |
| 式 (10)–(11) | 每包除以所有有效 tone 幅值和 | 与公式一致 |
| 1 秒窗口 | 按时间格选择最多 20 包；16 包即可判有效 | **不同**。论文实验固定 20 包；当前容许缺包是工程适配 |
| 式 (12)–(13) | 当前窗口时间均值并相减 | 与公式一致 |
| 第一层 ACF | FFT 零填充得到非负延迟线性相关，除零延迟 | 与式 (16) 基本一致；固定 `1/K` 在分子分母中抵消 |
| “cov”去均值 | 未沿子载波再次减均值 | 论文文字写 covariance，但式 (16) 没有均值项；当前选择匹配式 (16)，属于论文内部歧义 |
| 多层 ACF | 只保留非负延迟、保持长度 K，再递归自相关 | **无法确认严格一致**。递归思想符合正文和引用文献，但单/双边、长度及边界未公开 |
| `psi_n` | 固定取数组第 2 列，即 lag=1 | 对当前数组成立；但没有处理论文硬件与 AX210 的物理子载波间隔差异 |
| 时间汇总 | 默认对 `psi_n(t)` 求平均 | 符合“average”文字和 Fig. 6 尺度；不符合式 (19) 字面求和 |
| 多流汇总 | 默认对两个流求平均 | **明确不符合论文**，论文是跨流求和 |
| 判决/平滑 | 阈值可空；有阈值时因果三窗多数投票 | 阈值为空符合当前仅看曲线需求；投票方向基本一致，论文未说明起始边界 |
| 帧筛选 | 默认只保留 HE-SU；按 MAC/物理配置分组 | AX210 数据质量适配，不是论文算法 |
| 插值 | 路径输入关闭官方插值；工作区拖拽输入通常已经插值 | **同一数据可能因入口不同而得到不同 tone 数和分数**，复现条件不统一 |
| 数值精度 | 解析后保存为 single，运算时再转 double | 与论文 MATLAB 全 double 的可能实现不同，预期是次要差异 |

## 3. 最可能影响当前曲线的差异

### 3.1 物理子载波间隔没有对齐

这是当前最明确、最可能造成静态高基线的差异。

- 论文 80 MHz 平台提供 234 个可用子载波，对应传统 256-point OFDM 频率栅格，基本间隔约 312.5 kHz。
- 当前 AX210 HE-SU 数据原始为 996 tones，去掉 16 个导频后为 980 个有效 tones，`SubcarrierBandwidth=78125 Hz`。
- 当前代码取 `rho(:,2)`，即 AX210 的一个数组 lag，物理间隔约 78.125 kHz。

因此当前比较的是论文约四分之一的频率间隔。信道频响在更靠近的频点上通常更相似，静态残差的 lag-1 归一化自相关容易接近 1。已有审计中，把 AX210 tone 每 4 个抽取一个后，180803 的第一层均值由约 0.9913 降至约 0.9787，说明频率栅格确实影响很大；但第三层仍约 0.9688，因此它不是唯一原因。

严格按论文实验配置复现，应使用相同的 234-tone 表示。若在 AX210 上迁移算法，需要明确选择：按约 312.5 kHz 的物理间隔取 lag=4，或重采样到与论文一致的频率栅格。两者都属于 AX210 适配，需单独验证，不能称为作者源码的原样复现。

### 3.2 多层 ACF 的具体递推没有被论文完整定义

当前 `multiLayerACF` 把上一层**非负延迟部分**当作新信号，再求非负延迟 ACF。多层自相关参考文献只支持“上一层输出继续做自相关”这一原则，没有证明 RapidPD 作者使用相同的截取和边界。

这是高风险差异，因为自相关输出在零延迟附近本来就很平滑。对单边 ACF 再相关后取 lag=1，容易得到接近 1 的值。当前实测中，无人数据第 1 层已经约 0.990–0.991，第二层被进一步推到约 0.994，第三层约 0.992。第二、三层并没有形成论文 Fig. 6 所示的静态低值。

### 3.3 跨流平均与论文跨流求和不同

当前 AX210 是 1 Tx × 2 Rx，当前代码把两个流平均。论文是 2 Tx × 1 Rx，并明确对两个流求和。流方向不同本身不妨碍逐流计算，但最终组合规则不同。

改为求和只会把当前约 0.99 的分数放大到约 1.98，不能解决无人高基线；但它会改变阈值尺度，所以在声称复现前必须修正或明确报告。

### 3.4 AGC 补偿状态没有建立证据链

论文先描述 AGC 补偿后的幅值，再用总幅值归一化消除“不完美补偿”的剩余误差。当前代码直接读取 AX210 CSI，没有根据 `RxSBasic` 的 RSSI/AGC 字段做显式缩放，也没有证明 PicoScenes 的 `CSI` 已经是论文意义上的 AGC-compensated CSI。

逐包总幅值归一化会抵消理想的共同乘法增益，但不能保证抵消量化、饱和、每链路不同增益或固件内部平滑。这个差异可能使无人残差保留很强的频域结构。

### 3.5 数据入口不统一

直接传文件路径时，代码调用 `RXSParser(...,false)`，得到 980 tones；拖拽后传工作区变量时，PicoScenes 默认通常启用插值，审计中得到 1001 tones。两种入口并非同一预处理链。

现有数据上插值开关只使第三层均值变化约 0.00017，不能解释全部问题，但它使实验不可严格重复。比较 1M 和 NO 时必须固定同一种入口及 parser preference。

### 3.6 采集条件存在混杂变量

171616 的发射 MAC 为 `28:a0:6b:01:09:69`，180803 的发射 MAC 为 `68:34:21:ed:d0:cd`。两组数据不是完全相同的无线链路条件。当前曲线差异可能同时包含人体状态、设备/收发角色、位置或配置差异。

## 4. 当前可以下的结论

当前代码正确实现了 RapidPD 的外层框架和式 (10)–(16) 的主要计算，但没有足够依据称为“严格复现”。最主要的未闭合点是：

1. 234-tone 与 AX210 980-tone 的频率栅格不一致，`Δf` 被直接当成数组 lag=1；
2. 多层 ACF 的单/双边递推和边界规则没有作者源码佐证；
3. 跨流平均明确不同于论文求和；
4. AGC 补偿状态未验证；
5. 文件路径和工作区输入的插值条件不统一；
6. 运动和无人样本使用不同发射 MAC，实验对比存在混杂。

因此，当前 1M 约 0.9935、NO 约 0.9923 的曲线只能说明“这套具体实现能测到两组数据的相邻 tone 相关性略有差异”，不能作为 RapidPD 性能复现结果。

## 5. 后续修订顺序

1. 固定输入链：统一关闭 PicoScenes 插值，并记录 parser 版本、tone 数、中心频率、带宽和源 MAC。
2. 增加论文兼容的频率栅格模式：按物理频率选择 lag，至少比较 AX210 lag=1 与约 312.5 kHz 对应的 lag=4；更严格时构造固定 234-tone 映射。
3. 把多层 ACF 做成明确的候选实现并并排输出：当前单边递推、完整双边递推、论文式 (17) 字面版本；用论文 Fig. 5 的白噪声/正弦仿真先筛除不符合图形趋势的实现。
4. 将跨流组合改为论文的求和，同时保留每流 `phi`，避免只看整体值。
5. 验证 AX210 CSI 的幅值标定和 AGC/RSSI含义，明确归一化前的 `H` 是否已补偿。
6. 使用相同发射 MAC、频点、天线位置和配置重新采集成对的 1M/NO 数据，再评估分离度；不要在这一阶段拟合阈值。

只有完成前五项并能够重现论文 Fig. 4/5 的定性趋势后，才适合称为“按论文可见信息复现”；没有作者源码或补充说明时，仍不能称为逐实现严格复现。
